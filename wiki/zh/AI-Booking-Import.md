# AI 订单导入

**AI 解析** 扩展为 Tourism-Team 的订单导入添加了一个大语言模型兜底。当 [KDE Itinerary](Reservations-and-Bookings#import-from-booking-confirmation) 读不了一份确认文件时 —— 一封纯文本邮件、一种不常见的 PDF 版式、一个它不认识其格式的服务商 —— Tourism-Team 可以把文档交给 AI 模型，把它变成一条由你在保存前审阅的预订。

它是一个**可选启用的扩展，默认关闭**，并且可与自托管的本地模型配合工作，因此无需把任何订单数据送出你的服务器。

> **管理员：** 在 [管理：扩展](Admin-Addons) 中启用 **AI 解析**（它位于 *集成* 分组下）。此后订单导入即使没有 `kitinerary-extractor` 二进制文件也能工作 —— 在没有提取器时，模型会解析每个上传的文件，而不只是 Itinerary 读不了的那些。安装提取器仍是更好的配置：结构化票据保持快速且确定，模型则仍是兜底。不过，在让任何人使用它之前，请先配置好提供商和模型：扩展一开启 **从文件导入** 按钮就会出现，而既没有提取器也没有配置模型时，导入会直接失败。见 [预订与订单](Reservations-and-Bookings#import-from-booking-confirmation)。

## 它与常规导入如何配合

AI 解析并不取代 [KDE Itinerary](Reservations-and-Bookings) —— 它为其兜底：

1. 每个上传的文件都会先由 KDE Itinerary 解析。
2. 只有 Itinerary 对其返回**空结果**的文件会被送到 AI 模型。
3. 由于大语言模型提取不那么确定，AI 生成的每条预订在内部都会被标记为需审阅，导入会逐项引导你走常规编辑器，在保存前确认并修正它。该标记绝不会变成可见徽标：审阅编辑器会把每条预订保存为已审阅，因此一次保存下来的 AI 导入不携带 **待检查** 标记。

因此结构化票据继续以快速、确定的方式解析；AI 只在那些否则会失败的文件上介入。如果扩展被禁用，导入的行为与之前完全一致。在没有提取器的安装上没有什么可兜底的 —— 每个文件都直接交给模型。

## 选择提供商

该扩展支持三种提供商：

| 提供商 | 运行位置 | 说明 |
|----------|-----------|-------|
| **本地（Ollama）** | 你自己的硬件 | 无订单数据离开你的网络。推荐用于隐私场景；可在 CPU 上工作。 |
| **OpenAI** | OpenAI 的 API，或通过自定义 base URL 使用任何 **OpenAI 兼容** 端点 | 需要 API 密钥。 |
| **Anthropic** | Anthropic 的 API | 需要 API 密钥。**原生读取 PDF —— 包括扫描件。** |

> **扫描版 PDF：** 本地和 OpenAI 兼容模型收到的是文档的*提取文本*。扫描版或纯图片 PDF 没有文本层，因此这些提供商对其返回空结果。只有 **Anthropic** 会摄取原始 PDF，能够读取扫描件。

## 管理员：实例级配置

当你启用该扩展时，一个配置面板会直接出现在 [管理：扩展](Admin-Addons) 中它下方：

> *设置实例级配置（适用于所有用户）。留空则让每位用户配置自己的提供商。*

- **提供商** —— 本地 · OpenAI 兼容、OpenAI 或 Anthropic。
- **基础 URL** —— 除 Anthropic 外每个提供商都会显示。默认对本地 Ollama 服务器为 `http://localhost:11434/v1`，对 OpenAI 为 `https://api.openai.com/v1`。在此把它指向任何 OpenAI 兼容端点。
- **API 密钥** —— 对本地服务器可选（`(often not required)`），对云端提供商必填。以**加密**方式存储；保存后会以掩码（`••••••••`）显示，保持不变则会保留已存储的密钥。
- **模型** —— 模型 id（例如 `qwen3:8b`、`gpt-4o`、`claude-opus-4-8`）。

如果你在此设置了提供商和模型，它会适用于**所有用户**并覆盖他们的个人设置。让面板留空则让每位用户自带模型（见下文）。

### 拉取本地模型

选择 **本地** 提供商后，该面板会直接管理你的 Ollama 服务器：

- **服务器上已安装** 列出 Ollama 已有的模型，并带一个 **刷新** 按钮。点击某个模型即可选中它。
- **拉取推荐模型** 会下载一个模型并显示实时进度条。推荐的模型只有一个，**Qwen3 — 8B**（`qwen3:8b`）—— *CPU 上最佳的提取质量与速度（thinking 自动禁用）· Apache-2.0*。拉取完成后它会自动被选中。

你也可以选择服务器上已安装的任何其他模型，或手动输入模型 id。

## 按用户配置

如果管理员将实例配置留空，每位用户都可以在 **设置 → 集成 → AI 解析** 下配置自己的模型（该区块仅在扩展启用时出现）：

> *选择用于从上传文件中提取订单的 AI 模型。仅当你的管理员没有为整个实例配置模型时，此项才生效。*

这些字段是一个 **提供商**（此处只有 **OpenAI** 或 **Anthropic**）、一个 **模型** id，以及一个*加密存储*的 **API 密钥**（留空则保留当前密钥）。没有个人基础 URL：此服务器调用的地址属于实例配置，因此本地（Ollama）模型只能由管理员在扩展上设置，服务器对任何试图存储个人基础 URL 或个人 `local` 提供商的人（包括管理员）都会返回 403。

还有一个 **将文档作为图片发送** 开关。它按用户存储，但提取目前会忽略它：只有 Anthropic 会收到原始 PDF，其他所有提供商始终收到提取文本。

> **优先级：** 管理员的实例模型始终优先。个人设置只在没有配置实例级模型时才生效。

## 用 AI 导入一条预订

上传流程就是常规的订单导入 —— AI 只是在它背后运行：

1. 在行程规划器中，打开 **预订** 标签页并点击 **从文件导入**。
2. 把你的文件（EML、PDF、PKPass、HTML、TXT —— 最多 5 个文件，每个 10 MB）拖到上传区域。
3. 上传对话框会立即关闭，一个**后台小组件**（右下角）会显示 *正在解析文件…* 以及一个运行中的计数。它工作期间你可以继续在 Tourism-Team 中浏览；该小组件在页面重新加载后仍然存在，甚至会跟随你到其他页面。
4. 解析完成后，点击小组件的 **导入** 按钮开始审阅。
5. 每条解析出的预订都会**在常规的预订（或交通）编辑器中预填**打开，一次一条。在你逐条确认之前不会保存任何内容。

### 什么都没找到时

如果某个任务以 *无法从上传的文件中提取任何预订信息* 结束，小组件会提供一个 **尝试 AI 解析** 按钮。它会以强制 AI 模式重新上传相同的文件：完全跳过 KDE Itinerary，每个文件都直接交给模型。该提议只在结果为空时出现，并且绝不会出现在一次已被强制的运行上。如果实例级和个人模型都没有配置，重试会在卡片上以错误告终，而不是启动。

它是一次重试，不是另一条路径 —— 在常规导入中，模型已经看过 Itinerary 返回空结果的每个文件，因此它主要在该任务启动之后才配置了扩展或模型时才值得按。没有任何办法把一份 Itinerary *确实*读过的文档推给模型：只要解析产生了任何预订，小组件就显示 **导入**，没有重试按钮。这类预订请在审阅编辑器中修正。

### 会填入和创建什么

模型被要求捕获完整的预订 —— 包括**多段航班的每一段** —— 并且在保存时，Tourism-Team 会把每一项接入旅行：

- **字段** —— 预订/确认码、日期和时间，以及按类型：座位、舱位、站台、总价和货币；酒店会带上其地址，租车带上其公司，餐厅和活动带上其场馆及电话和网站。
- **地点** —— 只有 **酒店** 预订会变成旅行地点。保存时审阅编辑器会复用名称匹配的现有旅行地点；否则会对审阅后的地址做地理编码，创建并链接一个新地点，于是地图图钉就会出现。交通站点会在文件解析时做地理编码，但它们作为该预订的 **From → To 端点** 存储，而不是作为旅行地点 —— 无法定位的站点会在解析结果上列为警告，并在你保存时被丢弃，所以请先在审阅编辑器中修正它。餐厅和活动场馆只作为预订的位置文本到达：编辑器可以链接旅行中已存在的地点，但绝不会为你创建一个。
- **住宿** —— 一条酒店预订会在匹配的入住/退房日创建住宿。
- **关联费用** —— 如果 [费用扩展](Budget-Tracking) 已启用且该预订有价格，会创建一条关联支出。没有该扩展时，价格只留在预订上。
- **源文档** —— 上传的文件会附到该预订的文件中。

## 须知

- **无需手动迁移**，该扩展在界面中配置。它读取的唯一环境变量是 `LLM_TIMEOUT_MS`（见 [环境变量](Environment-Variables)）。
- **本地推理可能很慢。** 在仅有 CPU 的主机上，一条预订可能要花数十秒到几分钟；Tourism-Team 默认允许模型每个文档 15 分钟，`LLM_TIMEOUT_MS` 可以提高或降低它。上传按用户**一次一个**解析，因此多个文件会排队而不是并行运行。
- **解析任务在完成后会保留约 10 分钟**。请在该窗口内开始审阅。
- **隐私** —— 使用本地提供商时没有任何内容离开你的网络。使用 OpenAI 或 Anthropic 时，文档文本（对 Anthropic 则是 PDF 本身）会被发送给该提供商进行提取。
- **API 密钥绝不会以明文返回** —— 它们在静态时被加密，且只会以掩码形式显示。
