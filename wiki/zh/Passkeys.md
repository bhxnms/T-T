# 通行密钥

使用指纹、面容、PIN 或硬件安全密钥登录，无需输入密码。

## 在哪里找到它

打开 **设置** 并选择 **账户** 标签页。**通行密钥** 区域位于两步验证区块下方。

> **管理员：** 通行密钥登录默认关闭。在 **管理 → 设置** 的 **通行密钥登录** 卡片中打开 **启用通行密钥登录**。

当该功能关闭且你没有注册任何通行密钥时，该区域会完全隐藏。如果你已经有通行密钥，即使管理员之后关闭了该功能，列表仍会保持可见，因此你总能清理它们。

## 注册通行密钥

1. 点击 **添加通行密钥**。
2. 输入你的**当前密码** —— Tourism-Team 要求输入它是为了不让被劫持的会话悄悄植入一个通行密钥。
3. 可选地为该通行密钥起个名字（占位符会建议类似 `iPhone` 的名称）。留空则 Tourism-Team 会根据身份验证器把它命名为 **通行密钥（已同步）** 或 **通行密钥**。
4. 再次点击 **添加通行密钥**，并按你的设备提示操作（Touch ID、Windows Hello、Android 屏幕锁、YubiKey 等等）。

每个通行密钥都以*要求用户验证*注册，因此总会进行生物识别或 PIN 校验 —— 仅仅「轻触密钥」是不够的。同一个身份验证器无法在一个账户上注册两次，注册超过五分钟就会过期。

如果你关闭了浏览器对话框，会得到 **通行密钥设置已取消**，且不会存储任何内容。

## 使用通行密钥登录

在登录页面上，密码表单下方会出现一个 **使用通行密钥登录** 按钮（由一个 **或** 分隔线隔开）。点击它，在浏览器提示中选择你的通行密钥，你就会直接登录 —— 无需用户名，无需密码，无需第二步。

只有在以下条件全部成立时该按钮才会显示：

- 管理员已启用通行密钥登录。
- 该部署能解析出可用的 WebAuthn 域名（见[设置要求](#setup-requirements)）。
- 实例不处于仅 OIDC 模式。
- 你位于登录表单上（而不是注册、2FA 步骤或强制更改密码）。

Tourism-Team 绝不透露哪些账户有通行密钥：登录仪式使用可发现凭据，每次失败都返回相同的通用提示 *Authentication failed*，响应还会被填充到固定的最小延迟，因此时序不会泄露任何信息。

## 管理你的通行密钥

列表中的每个条目都显示它的名称、**已同步** 或 **此设备** 徽章、**添加** 的日期，以及带日期的 **上次使用** 或 **从未使用**。

- **重命名**（铅笔图标）—— 内联编辑名称；按 Enter 保存，按 Escape 取消。名称上限为 60 个字符。
- **删除**（垃圾桶图标）—— 以 *Remove this passkey? Confirm with your password.* 确认，并要求输入你的当前密码。

删除所有通行密钥绝不会把你锁在外面 —— 你的密码始终作为后备保留。

> **管理员：** 在 **管理 → 用户** 中，编辑用户会显示一个 **重置通行密钥** 操作，可一次移除该用户的全部通行密钥（用于设备丢失的情况）。该用户仍可用自己的密码登录。

## 通行密钥与两步验证

经过用户验证的通行密钥本身已经是两个因素 —— 持有设备加上生物识别或 PIN —— 因此它直接签发会话，之后**不会**再要求输入 TOTP 验证码。

同样的道理适用于管理员的 **强制要求两步验证（2FA）** 策略：只要拥有至少一个通行密钥，就像启用了一个 TOTP 身份验证器一样满足该策略。该策略下的全新用户可以注册一个通行密钥，而不必设置身份验证器应用；在 API 其余部分被封锁期间，注册端点仍然可达，因此没有人会被卡住。见 [两步验证](Two-Factor-Authentication)。

## 设置要求

通行密钥绑定到一个域名（*Relying Party ID*）。如果解析不出可用的域名，即使开关打开该功能也会保持隐藏，管理员卡片会显示一条警告。

> **管理员：** **通行密钥登录** 卡片还有 **Relying Party ID (domain)** 和 **Allowed origins** 字段。把它们留空即可从 `APP_URL` 推导出两者。之后更改 RP ID 会使已有的通行密钥失效。

两个值都可以用环境变量固定，它们优先于管理面板字段：

- `WEBAUTHN_RP_ID` —— 可注册域名，例如 `tt.example.com`。固定的值会被原样使用，因此它必须是真实域名：浏览器拒绝把裸 IP 地址作为 Relying Party ID。Tourism-Team 只对从 `APP_URL` 推导出的 RP ID 做这项检查 —— 那里的 IP 主机名解析不出任何东西，该功能会报告自己未配置。
- `WEBAUTHN_ORIGINS` —— 逗号分隔的允许来源，例如 `https://tt.example.com`。

两者的完整说明见 [环境变量](Environment-Variables)。

## 审计与速率限制

注册、删除和通行密钥登录都会记录在[审计日志](Audit-Log)中（`user.passkey_register`、`user.passkey_delete`，以及带 `method: passkey` 的 `user.login`）。如果某个身份验证器重放了一个过期的签名计数器，Tourism-Team 会拒绝那次尝试并记录 `user.passkey_clone_suspected`，但不会禁用该凭据。

登录和注册尝试按 IP 在 15 分钟窗口内限流。

## 权限

没有任何 Tourism-Team 权限门控通行密钥 —— 任何已登录用户都可以注册和管理自己的通行密钥。只有实例级开关和 WebAuthn 域名配置由管理员控制，**重置通行密钥** 操作仅限管理员。
