# 演示模式

演示模式让你运行一个公开的「先试用再安装」Tourism-Team 实例。访客可以使用一个共享的演示账户，该账户的写入操作被封锁，数据库每小时自动重置，让实例保持在已知状态。


## 启用演示模式

在你的环境中设置 `DEMO_MODE=true` 并重启 Tourism-Team。设置环境变量的方法见 [环境变量](Environment-Variables)。

演示模式启用后，登录页会显示一个一键 **「试用演示」** 按钮。点击它即可立即以演示用户身份登录 —— 无需输入任何凭据，也无需注册。

**演示账户（首次启动时自动创建）：**

| 字段 | 值 |
|---|---|
| 邮箱 | `demo@tt.local` |
| 密码 | `demo12345` |

**管理员账户：** 首次启动时也会初始化一个管理员账户。默认使用用户名 `admin`、邮箱 `admin@tt.local`、密码 `admin12345`。你可以在初始化时用 `DEMO_ADMIN_USER`、`DEMO_ADMIN_EMAIL` 和 `DEMO_ADMIN_PASS` 环境变量覆盖它们（它们仅在 `DEMO_MODE=true` 且首次启动、数据库尚未初始化时生效）。见 [环境变量](Environment-Variables)。

**升级已有的演示实例：** 更早的版本曾把这两个账户初始化为 `demo@trek.app` 和 `admin@trek.app`（再早是 `demo@nomad.app` / `admin@nomad.app`）。这些地址现在仍然会被识别，因此就地升级的实例无需重置即可继续工作：演示登录会找到记录所在的那一行，下面的各项封锁也依然对它生效。只有当确实找不到已有账户时，才会按上表的地址新建记录。

## 演示用户可以做什么、不能做什么

演示用户账户对共享的旅行数据有读取权限，但以下操作被永久封锁：

- **修改密码** —— 返回 403。
- **删除账户** —— 返回 403。
- **启用或移除两步验证** —— 返回 403。
- **上传文件** —— 头像上传、旅行封面上传，以及文档/照片附件都被封锁并返回 403。
- **所有 MCP 写入工具** —— 演示用户通过 MCP API 进行的创建、更新和删除操作都被封锁。

演示模式启用期间注册也会被禁用 —— 访客无法创建新账户。

管理员账户不受影响，保有完整访问权限。

## 每小时重置

Tourism-Team 会安排每小时自动重置演示数据库。每次重置时：

1. 当前的 `travel.db` 被替换为保存的基线（`travel-baseline.db`）。
2. 管理员账户的凭据（`password_hash`、API 密钥、头像）会在恢复的基线之上重新应用，因此管理员的 API 密钥和密码修改能在重置中保留。

如果还没有保存过基线，重置会被跳过并记录一条消息。

这项延续通过解析管理员记录所在的邮箱来查找：你设置了 `DEMO_ADMIN_EMAIL` 就用它，否则依次尝试当前默认值（`admin@tt.local`）和更早版本用过的地址。初始化和重置共用同一份候选列表，因此两者不会对「哪一行是管理员」产生分歧 —— 这一点很重要，因为被恢复的基线是初始化时写下的文件，可能带着其中任何一个地址。如果你自己改过账户名，仍然可以显式设置 `DEMO_ADMIN_EMAIL` 把查找固定到某一个地址。

存储在 `app_settings` 中的实例级 Maps 和 Unsplash 密钥无论哪种情况都会被延续，因此地图和照片搜索在重置后仍能正常工作。

## 保存基线

基线是每小时重置恢复到的快照。管理员可以随时更新它：

**端点：** `POST /api/admin/save-demo-baseline`

该功能在管理后台中可用。基线会捕获数据库的当前状态 —— 包括旅行数据、设置和加密的 API 密钥 —— 因此演示功能（地图、照片、天气）在每次重置后都能继续工作。

在演示模式启用下的首次启动时，Tourism-Team 会初始化三个示例旅行（Tokyo & Kyoto、Barcelona Long Weekend、New York City），归管理员所有并与演示用户共享，然后自动保存初始基线。

## 限制

- 演示模式不适合承载真实用户数据用于生产环境。每小时重置会删除所有访客创建的内容。
- 所有演示访客共用一个账户 —— 会话之间没有隔离。
- 演示用户的文件上传（照片、文档、旅行封面、头像）被禁用。
