# 安装：Windows（免安装版）

无需 Docker、无需事先安装 Node，即可在 Windows 上运行 Tourism-Team：下载一个 zip，解压，双击启动器即可。不写注册表、不做系统级安装 —— 删掉文件夹就等于彻底卸载。

> **这不是服务器部署的推荐方式。** 本包面向单台 Windows 机器 —— 笔记本、家用电脑。若要在常年开机的服务器上运行，请用 [Docker Compose](Install-Docker-Compose) 镜像：一条命令即可更新、以服务方式运行，文档其他部分也默认这种安装方式。对比见下方[如何选择安装方式](#如何选择安装方式)。

## 你将得到什么

```
TT-Travel-Planner-<版本>-win-x64.zip   （约 200 MB）
```

解压到任意位置（桌面、`D:\Apps\`、U 盘），文件夹内容如下：

| 路径 | 说明 |
|---|---|
| `TT Travel Planner.exe` | 双击它。自动选端口、启动应用、打开浏览器。 |
| `runtime\node.exe` | 应用所依赖的 Node 运行时 —— 你无需自行安装 Node。 |
| `app\` | 应用本体。 |
| `app\server\data\` | 你的数据库、日志和加密密钥。**请备份此目录。** |
| `app\server\uploads\` | 你上传的照片、文档和封面。 |
| `tt-port.json` | 首次运行时生成，记录所用端口。 |
| `README.txt` | 同样的说明，离线可读。 |

## 安装

1. 从 [Releases 页面](https://github.com/bhxnms/T-T/releases) 下载 zip（文件名以 `-win-x64.zip` 结尾）。
2. 右键 → **全部解压缩**，并保持所有文件在一起。**不要在 zip 压缩包内直接运行启动器**：Windows 会把它解到临时目录，数据会随临时目录一起被清理。
3. 双击 **`TT Travel Planner.exe`**。
4. 会打开一个控制台窗口。首次运行会创建数据库，并打印它生成的管理员账号 —— **请把密码记下来**，它只显示这一处。
5. 浏览器会打开 `http://localhost:3001`（或第一个可用端口，见下）。登录后按提示修改密码。

> **不要放在 `C:\Program Files\`。** Windows 限制对该目录的写入，应用将无法创建数据目录。请解压到用户目录或 `D:\`。启动器不需要管理员权限。

## 端口：冲突时会怎样

应用启动**之前**就会检查 3001 是否可用，因此端口冲突不会变成报错页面：

- 3001 空闲 → 直接使用。
- 3001 被占用 → 启动器自动顺延到下一个可用端口（最多向后找 20 个），并在控制台明确告知：

  ```
  [!] Port 3001 was in use - using 3002 instead.
  ```

成功使用的端口会写入 `tt-port.json`，下次启动继续用它，你的浏览器书签不会失效。

**要固定端口**，编辑启动器旁的 `tt-port.json`：

```json
{
  "port": 8080
}
```

若该端口也被占用，启动器同样会顺延而不是报错，并告知实际使用的端口。删除此文件即恢复自动选择。

> **为什么这在 Windows 上尤其重要。** 3000/3001 是热门端口 —— 其他开发服务器会占用，Hyper-V 的动态端口保留区也可能占住一段而看不到任何监听进程。服务端自身把监听失败视为致命错误（对容器是正确的：有重启策略兜底），所以这项检查放在启动器里做。

## 防火墙

首次启动可能弹出 Windows Defender 提示。除非你打算从其他设备访问，否则只勾选**专用网络**：

- **专用网络** —— 允许家庭网络内的其他机器访问。
- **公用网络** —— 在连接咖啡馆/酒店 Wi-Fi 的笔记本上请不要勾选。

无论如何，本机都可以通过 `http://localhost:<端口>` 访问：环回流量不经过防火墙过滤。该提示只影响其他设备能否访问。

## 开机自启

启动器就是普通程序，Windows 常规做法都适用：

- **登录时启动：** 按 `Win+R`，输入 `shell:startup`，把 `TT Travel Planner.exe` 的快捷方式放进打开的文件夹。
- **任务计划程序：** 新建任务，触发器选「登录时」，操作选「启动程序」并指向 `TT Travel Planner.exe`，「起始于」保持为解压目录。

应用运行期间会一直保留一个控制台窗口；**那个窗口就是应用本身**，关闭它即停止服务。

## 升级

你的数据位于 `app\server\data\` 和 `app\server\uploads\`，而新版本里这两个目录是空的。升级步骤：

1. 停止应用（关闭控制台窗口）。
2. 把 `app\server\` 下的 `data\` 和 `uploads\` 复制到安全位置。
3. 把新版本解压到**新文件夹**。
4. 把你保存的 `data\` 和 `uploads\` 复制进新版本的 `app\server\`，覆盖其中内容。
5. 启动新的启动器。数据库会在启动时自动迁移。

> **请务必保留 `app\server\data\.encryption_key` 的副本。** 它用于解密数据库中存储的密钥（API 密钥、两步验证种子、SMTP 与 OIDC 凭据）。该文件一旦丢失，这些值无法恢复，只能重新填写。它与数据库在同一目录，所以备份 `data\` 就一并覆盖了。

## 备份

全部状态就是两个目录：

```
app\server\data\      数据库、密钥与日志
app\server\uploads\   上传的文件
```

停止应用后把两者复制走即可。管理面板的 **管理 → 备份** 也能生成归档，具体包含内容见[备份](Backups)。

## 从外网访问：Cloudflare 隧道

管理面板的 **管理 → Cloudflare 隧道** 在这里同样可用，但与 [Cloudflare 隧道](Cloudflare-Tunnel) 里的 Docker 说明有一处不同：本包没有 compose 网络，连接器作为本机上的普通程序运行。

面板中因此有两项不同：

| 字段 | Docker | 本包 |
|---|---|---|
| **服务主机** | `app`（compose 服务名） | **`localhost`** —— `app` 在容器网络之外无法解析 |
| **服务端口** | `3000`（镜像固定端口） | **启动器实际选中的端口** —— 面板会自动填入本实例正在监听的端口，保持默认即可 |

面板会针对原生安装自动填好这两项，所以实际操作中你直接接受默认值即可。

然后在同一台机器上运行连接器：

1. 从 Cloudflare 的 [releases 页面](https://github.com/cloudflare/cloudflared/releases) 下载 `cloudflared-windows-amd64.exe`，改名为 `cloudflared.exe`。
2. 在该目录打开终端，运行面板给出的命令，并填入隧道教程第 3 步得到的连接器令牌：

   ```powershell
   .\cloudflared.exe tunnel --no-autoupdate run --token <你的连接器令牌>
   ```

   不需要写配置文件 —— 路由规则已经存放在 Cloudflare 的配置里。

这个窗口需要和应用窗口一起保持开启。若希望连接器开机自启，可将其注册为 Windows 服务（需在**管理员**终端中执行）：

```powershell
.\cloudflared.exe service install <你的连接器令牌>
```

> **域名返回 502 说明服务主机填错了。** 连接器会正常启动、DNS 也能解析，但每个请求都失败 —— 因为它拨向了一个无法访问的地址。本包的正确值是 `localhost` 加上启动器启动时打印的端口。

## Windows 上不可用的功能

- **从邮件或 PDF 导入订单。** 它依赖 `kitinerary-extractor`，一个以 Linux 二进制形式提供的 KDE 组件。应用检测不到时会禁用该导入路径；替代方案是 AI 解析（见 [AI 订单导入](AI-Booking-Import)），其余功能不受影响。
- **本 Wiki 中基于 `docker` 的升级说明** —— 那些说明针对容器镜像，不适用本包。

其他一切 —— 行程、地图、足迹、手动录入的订单、费用、行李清单、协作、内置帮助 —— 都与文档描述完全一致。

## 疑难排查

| 现象 | 原因与处理 |
|---|---|
| 控制台窗口一闪而过 | 你是以「退出即关闭」的方式启动的。在该目录打开终端，运行 `"TT Travel Planner.exe"` 即可看到提示信息。 |
| 提示「下载不完整」 | 有文件未解压出来（常见于直接双击 zip 打开而非解压，或杀毒软件隔离了 exe）。请重新完整解压。 |
| 提示「3001-3020 端口全部被占用」 | 有程序占住了整段端口。在 `tt-port.json` 里换一个端口（如 `8080`），或用 `netstat -ano \| findstr :3001` 找到占用进程并关闭。 |
| 浏览器打开是空白页 | 首次运行时数据库仍在迁移。等几秒后刷新；控制台打印 `Ready` 即表示已就绪。 |
| 忘记管理员密码 | 停止应用，在该目录运行 `runtime\node.exe app\server\reset-admin.js`，它会打印新的管理员密码。见[疑难排查](Troubleshooting)。 |
| 杀毒软件删除了启动器 | 会启动本地服务的未签名可执行文件有时会触发启发式规则。请从隔离区恢复，并为该文件夹添加排除项。 |
| 端口正确但页面打不开 | 查看控制台窗口里的真实错误，以及 `app\server\data\logs\trek.log`。 |

## 如何选择安装方式

| | Windows 免安装版 | Docker Compose |
|---|---|---|
| 需要 Docker | 否 | 是 |
| 需要预先安装 Node | 否 | 否 |
| 开机自启 | 任务计划程序或启动文件夹 | `restart: unless-stopped` |
| 升级方式 | 解压新 zip，迁移 `data`/`uploads` | `docker compose pull && up -d` |
| 应用内更新提示 | 支持 | 支持 |
| 从邮件/PDF 导入订单 | **不支持**（组件仅限 Linux） | 支持 |
| 多架构镜像 | 仅 x64 | amd64 + arm64 |
| 适合场景 | 单台 Windows 电脑 | 家庭服务器、NAS、VPS |

## 自行构建本包

本包由脚本生成，无需手工组装：

```bash
node packaging/windows/build-windows.mjs
```

在 Windows 上，它内嵌宿主自身的 `node.exe`，并按常规方式安装 `better-sqlite3` 的原生模块。在 Linux 上则为交叉构建：下载版本匹配的 `node.exe`，并向 better-sqlite3 的发布页请求与该 Node 版本精确对应的 **win32-x64** 预编译包 —— 否则按宿主平台构建会打进一个 Linux 二进制，安装过程毫无异常，却在用户机器上第一次查询数据库时失败。脚本在打包前会校验暂存目录（包括确认原生模块确实是 Windows 二进制、且不含任何符号链接），因此这类失败不会流入正式版本。

对应的 GitHub 工作流为 `.github/workflows/windows-package.yml`（手动触发，产物以构建附件形式上传）。
