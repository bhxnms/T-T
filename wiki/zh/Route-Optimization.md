# 路线优化

Tourism-Team 会计算你的地点之间的步行和驾车时间，并可以重新排序以最小化总行程距离。

![路线优化](assets/OptimizeRoute.png)

## 路线计算

Tourism-Team 使用 **OSRM**（Open Source Routing Machine）计算所选日期内相邻地点之间的路线。无需 API 密钥。

日程计划页脚中的路线开关提供**驾车**和**步行**两种方案（各自在对应的 OSRM 网络上规划）。已安装的插件可以增加更多方案：带有 `routeProvider` 钩子的插件 —— 例如一个规划充电停靠点的电动出行插件 —— 会作为驾车/步行之外的一种额外模式出现。选中这样的方案后，由该插件计算当天的路线：其几何形状绘制在地图上，规划的停靠点（例如充电站）在线条上显示为小圆点，路段连接线则显示该插件的行程时间以及它附加的任何说明（「充电 25 分钟」）。如果插件失败或超时，Tourism-Team 会回退到直线，与 OSRM 服务中断时的表现完全一致。

该开关设置的是**当天**的默认出行方式。它保存在这一天上，因此一次旅行中每一天都可以不同，选择在重新加载后依然保留。

单个路段可以覆盖当天默认值：点击两条条目之间的连接行，为这一个路段单独选择**驾车**、**步行**或任何插件方案，或选择**使用当天默认值**来清除覆盖。同样的菜单也出现在往返当天住宿的连接线上，以及到达交通预订之后的连接线上 —— 在那里它设置的是*到达*该停靠点这一路段的模式。每条连接线都显示该路段实际绘制时所用模式的图标和时间。

当旅行有开始和结束日期，且你可以编辑这一天时，该菜单还会多出一项**公共交通**。它会打开自动交通搜索（见 [交通：航班、火车、汽车](Transport-Flights-Trains-Cars)），并已预填好该路段的两个端点和你正要离开的那一站点的出发时间。

路线分段会在两个地点之间的任何交通预订（航班、火车、汽车、巴士或邮轮）处重置 —— 那一段不是驾车也不是步行，因此不会跨越它绘制地面路线。

## 路线显示

- 彩色线段在地图上连接相邻的地点。
- 在每一对相邻地点之间，日程计划中的一条细连接行显示该路段的行程时间和距离，并带有其规划模式的图标。
- 插件可以向日程计划附加时间条目（例如某个停靠点计划的充电时间、航班前的安检缓冲时间）。它们以细行形式出现在所属地点或预订的下方，其分钟数会以「+X min」的形式计入当天页脚总计。

## 优化路线

当天路线工具中的**优化**按钮会重新排序当天的地点，以最小化总行程距离。**最近邻**遍历先产生一个良好的起始顺序，然后**2-opt**遍历化解该遍历遗留下来的交叉 —— 两者都按直线（欧几里得）距离度量。

启用**从住宿优化路线**（设置 → 常规 → 旅行与地图，默认开启）时，优化以当天的酒店为锚点：要么从酒店出发再回到酒店形成一个环线，要么在中转日做一段酒店到酒店的行程。关闭该设置，或者当天住宿没有坐标时，它改为从第一个地点开始。地点少于三个的一天在桌面端会被跳过，移动端的日程浮层也只从三个起提供该按钮。而计划界面 **计划** 模式中的**优化**操作没有这个下限 —— 两个带坐标的可移动地点就够了，如果由酒店作为锚点，这两个地点甚至也能互换。

只有自由的地点会被重新排序。如果你锁定了某个地点，或者它设置了时间，它就会保留自己的位置 —— 带时间的停靠点由时间锚定。这些停靠点留在原地，被重新排序的地点填补它们之间的空档。移动端没有锁定功能，因此只有设置的时间才能固定一个停靠点。

重新排序后可以用随即出现的撤销操作立即撤销。

## 在地图应用中打开这一天

当天路线工具中的三个图标按钮把当天的行程交给外部地图或离线导航应用，按照计划顺序使用其地点，并以当天的住宿作为首尾，与绘制出的路线完全一致。

**在 Google 地图中打开**会构造一个 `https://www.google.com/maps/dir/lat,lng/lat,lng/…` URL，按顺序包含所有停靠点，并在新标签页中打开。只有一个停靠点的一天则改为以该点打开地图搜索。

**在高德地图中打开**按照计划顺序把当天的地点交给高德地图，并包含真实的住宿首尾。一日只有一个停靠点时会打开高德标记。所有中间停靠点都会被保留：该链接使用带索引的 `ditu.amap.com/dir` 形式，因为高德 `navigation` URI 只接受一个途经点，其余会被静默折叠进第一个途经点的名称里。坐标在发送前会从 WGS-84 转换为 GCJ-02 —— 与标记 URI 不同，该端点没有可以声明坐标系的 `coordinate` 参数，未转换的链接在中国境内会偏移几百米。名称中的逗号也能完整保留，而在高德的 `lng,lat,name` 形式中会被截断。

**在 CoMaps 中打开**（旁边的指南针图标）把同一天交给 CoMaps 用于离线导航，并带上当天的出行方式 —— 当天自己的默认值，若当天没有默认值则为当前的路线方案。恰好两个停靠点的一天会以该模式的真实逐向路线发送过去（步行按行人、骑行按自行车，其他都按车辆）。其他任何一天都以命名地标点的形式发送过去，因为 CoMaps 的路线链接只接受起点和终点、中间什么都不接受，而把整天交出去总比默默丢掉计划中段要好。若要把完整行程作为一条可导航的轨迹，请使用 GPX 导出。

两个按钮在移动端也同样存在，位于日程浮层中。
