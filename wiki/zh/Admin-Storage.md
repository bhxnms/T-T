# 管理：存储

**存储** 标签页（管理后台 → 存储）控制 Tourism-Team 把每一类内容存放在哪里：存在哪些存储后端、哪个内容分类写入哪个后端，以及写入是否复制到额外的后端。在托管/代管实例上该标签页是隐藏的 —— 存储是运营方的事。

## 后端

后端是字节可以存放的一个具名位置。开箱即有两个：

| 后端 | 它是什么 |
|---------|------------|
| `uploads-local` | 本地 `uploads/` 目录（Docker 中的 `/app/uploads` 卷） |
| `backups-local` | 本地 `data/backups` 目录 |

你可以**编辑**一个内置后端来重新安置它的根目录，也可以**添加**以下类型的后端：

- **Local** —— 服务器可访问的磁盘或挂载上的一个目录。
- **S3** —— 任何兼容 S3 的服务（AWS S3、Cloudflare R2、Backblaze B2、Garage、MinIO/AIStor）。端点 URL、存储桶、凭据，以及可选的区域、键前缀、重试次数和超时。对于自托管端点，除非你的服务器配置了虚拟主机式存储桶寻址，否则请在 URL 中使用 IP 地址或 `localhost`。

如果设置了 `TREK_PLACE_PHOTO_DIR`，还会出现一个只读的 `place-photos-local` 后端 —— 它由该环境变量定义，而不是由本面板定义。

### 复制（镜像目标）

编辑任意后端并勾选一个或多个**镜像目标**：此后对该后端的每次写入也会被复制到每个选中的目标。移除全部目标即再次关闭复制。

- 一个后端可以充当**镜像目标或分类目标，但不能两者兼有** —— 列表中只提供没有存放任何分类的后端，混合这两种用途的配置在保存时会被拒绝。同步会让目标与它的后端**匹配**（见下文），因此存放在那里的其他内容都会被删除。
- 写入先到达后端本身（它始终是事实来源），然后按顺序到达每个目标。一个缓慢或不可达的目标会拖慢该后端上每个分类的每一次上传 —— 这对备份很理想，但在复制行程文档这类热分类之前值得权衡。
- 副本失败**绝不会让原始请求失败**。它们会被记录，并显示在标签页顶部的 **健康状态** 条中，包含后端、对象、操作以及发生在多久之前。空条意味着每一次被复制的写入都成功了。副本失败也会通知管理员 —— 通过应用内通知以及所配置的 webhook/ntfy/邮件渠道（首次失败立即通知，之后每个后端每小时最多一份摘要）。偏好设置在管理的「通知」标签页中。
- 复制从下一次写入开始。要复制在你添加目标之前就已存在的对象，请在后端所在行点击 **立即同步** —— 一次只运行一个同步，带进度和取消按钮；已存在且大小匹配的对象会被跳过，单个对象的失败会进入健康状态条而不会中止本次运行。同步会让目标**匹配**后端，而不只是追平：它还会删除后端上已不存在的目标对象 —— 它不是垃圾桶，所以只在你希望目标被修剪到一致时才运行它，误删会像其他任何副本失败一样进入健康状态条。

### 测试

每个后端行都有一个 **测试** 按钮：服务器在后端上写入、检查并删除一个小探针对象（`trek-probe/…`）—— 对于被复制的后端，会在后端本身和每个目标上分别进行 —— 并报告每个目标的结果。「Connection OK」意味着凭据、存储桶和可达性都通过检查。目标必须先**保存**，测试才能探测它们；刚添加、尚未保存的后端被用作目标时会报错，直到你保存。

## 分类

Tourism-Team 存储的每一类内容都属于八个分类之一，每个分类恰好分配给一个后端：

| 分类 | Id | 它存储什么 |
|----------|----|----------------|
| 行程文档 | `files` | 上传到行程的文件附件 —— 票据、PDF、预订确认函，以及行程聊天中分享的文件 |
| 旅程照片 | `journey` | 附加到旅程条目的照片和缩略图 |
| 封面图片 | `covers` | 行程和收藏的封面图片，包括从 Unsplash 获取的封面 |
| 个人头像 | `avatars` | 用户账户的头像 |
| 地点图片 | `places` | 附加到地点和收藏地点的图片 —— 上传或导入的 |
| Google 照片缓存 | `photos-google` | Google Places 照片的缓存副本 —— 可重新获取，丢失无妨 |
| Tourism-Team 照片缓存 | `photos-trek` | 照片（Memories）所用的 Tourism-Team 照片服务的缓存照片 —— 可重新获取，丢失无妨 |
| 备份 | `backups` | 由备份面板或计划任务创建的服务器备份归档 |

重新分配分类会改变**新**对象的存放位置。如果该分类下已有对象，面板会先询问：**移动现有对象**会把所有内容复制到新后端，切换分类，然后清扫任何与复制并行的写入；**只路由新写入**保持原有行为 —— 新对象进入新后端，现有对象留在原处并继续从它们已在的位置提供服务。复制 Google 照片缓存或地点图片被标记为不推荐 —— 两者存放的都是可重新获取或源自提供商的内容。

更早版本的 Tourism-Team 写入的旧 `/uploads/photos` 目录不是一个分类：它的文件仍会被提供并包含在备份中，但已没有任何东西写入那里，也无法重新分配它。

### 移动分类的对象

分类迁移与镜像同步共用它的一次一个的槽位（见上文*复制*）—— 在同步（或另一次移动）运行时开始一次移动会被拒绝，反之亦然。进度（已完成/总数，已复制/已跳过/已失败）会内联显示，并带取消按钮。

在分类切换之前取消是完全安全的：尚未发生任何改变，复制只是停止。复制失败的行为也一样 —— 只要有任何一个对象复制失败，分类就绝不会被切换。一旦切换已经发生，增量清扫（捕捉复制运行期间落到旧后端上的写入）总会运行到完成，即使你取消。

移动完成后旧对象**不会**被删除 —— 这正是那行可回收提示的含义（`N objects (size) remain on <backend> — reclaim manually`）。它被刻意留下，以便你在自行移除之前确认新后端看起来正确。

## 用量

「后端」区块显示每个后端和每个分类的对象数量与大小，每晚扫描（服务器时间 04:15），也可通过 **刷新** 按需扫描。时间戳显示这些数字是何时计算的 —— 重新分配分类不会追溯移动它们，要等到下一次扫描。上传后端的合计包含旧的照片库。

## 密钥与加密

后端凭据（S3 秘密访问密钥）以加密形式存储。建议显式设置 `ENCRYPTION_KEY` 环境变量 —— 不设置则使用持久化在数据目录中的隐式密钥，它能工作，但会随备份归档一起传播（持有备份的人可以解密其中包含的密钥）。如果你之后要从隐式密钥改为显式密钥，请遵循 [[加密密钥轮换|Encryption-Key-Rotation]] —— 直接设置新密钥会让已存储的密钥成为孤儿。已保存的密钥会显示为掩码占位符；编辑时不动掩码即保留已存储的值。

## 首次启动时的预置（种子文件）

对于脚本化部署，把 `storage-config.json` 放在数据目录中（在 Docker 中：把它挂载到 `/app/data/storage-config.json`）。它只会被导入一次 —— 在第一次没有任何已存储存储配置的启动时 —— 之后被忽略（日志中会有一行说明）。无效的文件会以确切的验证错误中止启动。

```jsonc
// storage-config.json - secrets may be plaintext (encrypted on import)
// or already-encrypted enc:v1: values.
{
  "backends": [
    { "name": "off-site", "type": "s3", "options": {
      "endpoint": "https://s3.example.com", "bucket": "trek",
      "accessKeyId": "...", "secretAccessKey": "..." } },
    { "name": "backups-mirror", "type": "mirror", "options": {
      "primary": "backups-local", "replicas": ["off-site"] } }
  ],
  "categories": { "backups": "backups-mirror" }
}
```

面板把这套确切的设置呈现为 `backups-local` 上的 **镜像目标**。

```yaml
# docker-compose: add under the trek service's volumes
      - ./storage-config.json:/app/data/storage-config.json:ro
```

要重置存储配置（或重新导入种子文件）：停止服务器，执行 `sqlite3 data/travel.db "DELETE FROM app_settings WHERE key LIKE 'storage.%';"`，然后再次启动 —— 它会以内置默认值启动，如果存在种子文件则重新导入它。

**恢复的先有鸡还是先有蛋问题：** 备份包含存储配置。如果你唯一的备份存放在 S3 上，而凭据就在其中：启动一个全新实例，在这里输入 S3 凭据（或挂载种子文件），然后从备份面板恢复。
