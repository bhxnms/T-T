# 应用内通知

Tourism-Team 可以就你的旅行中发生的事情通知你：一条邀请、一笔被修改的预订、
共享旅行中的一条消息、一项即将到期的待办。本页介绍**应用内收件箱** ——
也就是你在应用里读到的通知。通过电子邮件或 Webhook 投递的方式见 [通知](Notifications)。

## 收件箱

导航栏中的铃铛打开最近通知的列表。每条通知都会显示发生了什么、由谁操作、在何时发生，并且通常会链接到相关对象 —— 点击一条预订通知会在该预订处打开对应的旅行。

未读条目会显示在铃铛上计数。打开收件箱不会静默地把所有内容标为已读；你可以有意地清空它们。

同一列表还有整页视图，可以从铃铛进入，或直接访问 `/notifications`。它主要是为手机准备的，因为在那里下拉菜单过于局促。

## 你会收到哪些通知

事件集合由应用固定：

| 事件 | 触发时机 |
|---|---|
| 旅行邀请 | 有人邀请你加入某个旅行 |
| 预订变更 | 你所在的旅行中添加或修改了一笔预订 |
| 旅行提醒 | 某个旅行即将开始 |
| 待办到期 | 某个待办事项接近或已过截止日期 |
| 假期邀请 / 共享 | 假期合并请求和共享日历 |
| 收藏邀请 | 有人与你分享了一个收藏 |
| 照片已分享 | 你所在的旅行中添加了照片 |
| 协作消息 | 某个旅行的协作聊天中有新消息 |
| 行李分配 | 你被分配到某个行李分类 |
| 有新版本 | 存在更新的版本（管理员） |

## 控制你接收的内容

**设置 → 通知** 展示一个事件与投递渠道的矩阵，它同时作用于应用内收件箱和其他渠道。关闭某个事件会阻止它到达任何地方，包括铃铛。

这里有两层：

- **实例渠道** —— 由管理员决定本实例提供哪些投递渠道（应用内、电子邮件、Webhook，以及任何插件提供的渠道）。
- **你的偏好设置** —— 在实例提供的范围内，你选择哪些事件能到达你这里。

没有明确偏好设置的事件默认开启。这个矩阵是用来*退出*的，而不是你必须填写的清单。

通知邮件遵循你账户的语言，并发送到账户上的邮箱地址。

## 提醒与时机

旅行提醒和待办提醒不是即时事件 —— 它们是排定的。旅行提醒在旅行开始前固定天数触发；待办提醒有它自己的提前时间。两者都按计划而非在页面加载时计算，因此即使你从不打开应用，提醒也会送达。

提醒的提前时间对旅行是每次旅行的设置，对待办事项是实例级默认值。
