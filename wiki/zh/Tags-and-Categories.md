# 标签与分类

Tourism-Team 有两套相互独立的地点标注系统：

- **全局地点分类** —— 由管理员维护，在实例上的所有用户之间共享（例如 `Restaurant`、`Museum`）。
- **个人标签** —— 以用户为范围的标注（例如 `hidden gem`、`kid-friendly`）。


## 全局地点分类

分类对所有旅行中的地点进行归类。每个用户看到的都是同一套分类。

**每个分类的字段：**

- **名称** —— 显示在地点表单和侧边栏筛选器中。
- **颜色** —— 用于地图标记和地点侧边栏中带色图标背景。默认值：`#6366f1`。
- **图标** —— 一个 Lucide 图标名（例如 `MapPin`、`Coffee`、`Mountain`）。界面表单默认为 `MapPin`；数据库层面的回退值是 📍 emoji，渲染时它同样会被解析为 `MapPin` Lucide 图标。

分类出现在：

- 添加或编辑地点时的**地点表单**。
- **地点侧边栏**，作为筛选项。
- **地图标记** —— 分类图标和颜色用于为每个地点的标记图钉设定样式。
- **地图提示框** —— 悬停某个标记时显示分类名称和图标。

> **管理员：** 在 [管理：分类](Admin-Categories) 中创建和管理分类。只有管理员可以创建、编辑或删除分类。所有用户都可以读取。

## 个人标签

标签是每个用户自己的个人标注。它们通过多对多关系（`place_tags` 表）附加到单个地点上，因此同一个标签可以应用到任意多个地点，而单个地点也可以携带多个标签。

**每个标签的字段：**

- **名称** —— 自由文本。
- **颜色** —— 与标签名一同显示的十六进制值。默认值：`#10b981`（翠绿色）。

标签归其创建者所有，但只有那个*列表*是私有的。`GET /api/tags` 和 `list_tags` MCP 工具只返回你自己的标签，而标签名没有唯一性约束，因此不同用户 —— 甚至同一用户 —— 都可以创建同名标签而不产生冲突。

你附加到地点上的标签**不是**私有的。它会成为该地点的一部分：地点回读时以 `place_tags` → `tags` 联结且不带所有者过滤，因此每位旅行成员都能从 `GET /api/trips/:id/places`、日程和分配端点，以及 MCP 的 `list_places` 工具和 `trek://trips/{tripId}/places` 资源中获得它 —— 仅由旅行访问权限把关。地点列表上的 `?tag=` 筛选同样不是以用户为范围的，因此成员可以按同行旅伴的标签 ID 进行筛选。这是有意为之：只要标签的所有者还在旅行成员名单中，该标签就会被保留，所以当另一位成员重新保存该地点时，同行旅伴的标签不会被悄悄剔除。而属于旅行之外某人的标签则会被丢弃。

如果某次旅行有启用了地图/行程部分的公开分享链接，那么**安排在某一天**的地点的标签也会传达给匿名查看者 —— 只保留标签的 ID、名称和颜色，因此所有者的用户 ID 永远不会离开服务器。共享地点池中未安排日程的地点不携带任何标签。

实际上，这些标签是通过 API 和 MCP 而不是在应用里浮现的 —— 目前还没有任何视图会渲染地点的标签。删除标签会自动把它从所有已附加的地点中移除。

### 在哪里管理它们

目前标签主要通过 MCP API 暴露 —— 连接到你的实例的 AI 助手可以列出、创建、更新和删除标签（`list_tags`、`create_tag`、`update_tag`、`delete_tag`），并通过地点端点把它们附加到地点上。专门的标签管理 Web 界面尚不可用；地点 API 上以及 MCP `list_places` 工具上的 `tag` 筛选参数确实支持在标签存在后按标签 ID 筛选地点（`trek://trips/{tripId}/places` MCP 资源只按 `assignment` 筛选）。

> **AI / MCP：** 完整的标签工具列表见 [MCP 工具与资源](MCP-Tools-and-Resources)。

## 何时用哪一种

| 使用场景 | 使用 |
|---|---|
| 按类型对地点分类（餐厅、博物馆、徒步路线……） | **分类** |
| 你想应用到特定地点的个人标注 | **标签** |
