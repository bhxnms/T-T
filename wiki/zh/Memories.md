# 照片（照片来源）

**照片**把 Tourism-Team 连接到你已经在运行的某个照片库，这样旅行和日志照片就可以来自那里，
而不必手工上传。它是你的照片服务器与旅程相册之间的桥接层。

照片本身在应用中没有自己的页面。它在**设置 → 集成**下配置，其照片会出现在任何
展示图片的日志或旅行中。

## 支持的照片来源

| 照片来源 | 是什么 | 凭据 |
|---|---|---|
| **Immich** | 自托管的照片和视频库 | 服务器 URL + API 密钥 |
| **Synology Photos** | Synology NAS 照片应用 | NAS URL + 用户名/密码（或会话） |

两者都按用户配置：每个人连接自己的账户，因此共享的旅行不会合并所有人的照片库。

## 设置

### Immich

1. 打开**设置 → 集成 → 照片**。
2. 输入你的 Immich **服务器 URL**（你打开 Immich 所用的地址）以及一个在
   Immich 的 *账户设置 → API 密钥* 下创建的 **API 密钥**。
3. 按下**测试** —— 对话框会报告是否连接成功、以哪个账户完成认证，以及
   它解析出的规范 URL。

> **位于私有网络上的 Immich：** 如果 Immich 运行在 LAN 地址上，SSRF 防护默认会
> 拦截它。如果你打算访问本地服务器，请设置 `ALLOW_INTERNAL_NETWORK=true`（见
> [内网访问](Internal-Network-Access)）。否则应用会报告连接被阻止，而不是
> 一直挂起。

### Synology Photos

1. 输入 NAS URL、用户名和密码。
2. **跳过 SSL 验证**可用于使用自签名证书的 NAS。开启它只会为该连接
   禁用证书校验 —— 这是为可信的家庭网络提供的便利，而不是应该在公网上
   启用的东西。
3. 按下**测试**以确认登录。

当 URL 或账户发生变更时，Synology 会话可能过期或失效。出现这种情况时，
应用会清除已存储的会话，你需要重新登录；会有通知告诉你原因。

## 使用照片来源中的照片

连接之后：

- **旅程相册**可以浏览并从已连接的照片来源导入照片，而不只是
  接受上传。
- **照片搜索**可以在应用内跨你的照片库进行，并按照片来源筛选。
- 在有些流程中导入的照片是被引用而非复制的，在另一些流程中则会被缓存，因此大型
  照片库不必被复制一份。缓存的缩略图可以重新生成，并且会被排除在
  备份之外。

## 自动采集

在连接了某个照片来源后，旅行期间拍摄的带位置标记的照片可以被自动拉取到该次旅行的
日志中 —— 回填过程会遍历你的照片库，把照片与该次旅行的日期和
地点进行匹配，并附加吻合的那些。这正是让日志在旅行结束后自动填充、
而不必手动整理的原因。

## 照片不做的事

- 它不修改你的照片库。照片只被读取和引用；不会回写任何内容。
- 它不替代旅程。旅程拥有日志及其自己的上传；照片只是它可能的
  图片来源之一。
- 未启用旅程扩展时它无法工作 —— 照片来源源自旅程扩展。
