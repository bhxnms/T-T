# AMap（高德地图）

[AMap](https://www.amap.com/)（高德地图）是中国的地图服务提供商。Tourism-Team 可以用它做地点搜索、
POI 发现、照片、路线规划和导航 —— 而且在中国大陆，对中国地址、名称和营业时间来说，
它通常是比 Google Maps 或 OpenStreetMap 更好的数据源。

它完全是可选的。没有 AMap 密钥时，应用会回退到 Google Places（如果配置了 Google 密钥）
或 OpenStreetMap，一切照常可用。

## 为什么坐标看起来不一样

AMap 返回的是 **GCJ-02**，一种中国坐标偏移标准，所有中国的地图服务商都必须使用。Google、OpenStreetMap 和 Tourism-Team 自己的数据库都用 **WGS-84**。

Tourism-Team 在边界处进行转换：

- 从 AMap **进入**的每个坐标，在存储或绘制之前都会从 GCJ-02 转换为 WGS-84。
- 发往 AMap 的每个坐标（路线请求、导航链接）都会从 WGS-84 转换为 GCJ-02。

结果是：通过 AMap 找到的地点会落在 OpenStreetMap 瓦片的正确位置上，向 AMap 请求的路线也会沿着这些瓦片上实际绘制的道路走。这个转换永远不需要你来做。

> **关于中国地图服务商：** 两套系统之间的偏移约为 50–500 m，
> 足以把标记放到街道的错误一侧。如果你在使用中国底图时看到标记持续
> 偏移，那么坐标框架就是需要检查的地方。

## 密钥

AMap 有两个独立的密钥，用途不同。两者都由管理员填写。

| 密钥 | 在 AMap 控制台中的位置 | 用途 |
|---|---|---|
| **Web Service key**（`amap_api_key`） | 应用管理 → 我的应用 → Web服务 | 服务端搜索、POI 查询、地点详情、照片，以及驾车/步行/骑行路线。绝不会发送到浏览器。 |
| **JS API key**（`amap_js_api_key`） | 同一应用，**Web端(JS API)** 类型 | 当 高德 被选为底图提供商时，用于浏览器端的地图渲染。 |

**管理 → 设置** 中存放 Web Service 密钥。JS API 密钥与其他地图设置放在一起 —— 见 [地图设置](Map-Settings)。

部分 AMap 服务要求密钥开通了对应的 API 类型。如果搜索或路线规划返回 `INVALID_USER_KEY` 或 `SERVICE_NOT_AVAILABLE`，通常说明密钥存在但缺少该 API 类型，或者账号尚未完成实名认证。

## 启用 AMap 搜索

**管理 → 扩展 → 地图** 里有 **使用高德搜索地点** 开关
（`amap_search_enabled`）。开启后，地点搜索框会优先查询 AMap；如果 AMap 返回空结果或出错，则回退到原生提供商。

单次搜索可以覆盖实例默认值：地点搜索表单有一个提供商切换（高德 / 原生），因此某个用户无需改动实例设置就能搜索另一个提供商。

这个开关需要 Web Service 密钥。开关开启但没有存储密钥时，搜索会静默降级到原生提供商，而不是直接失败。

## AMap 支持哪些功能

### 地点搜索与 POI 详情

地点搜索返回名称、地址、坐标、评分、营业时间、电话号码、分类和照片。结果排序由 AMap 自己决定。

### POI 探索

地图上的探索浮标可以列出某个分类附近的 POI（餐厅、咖啡馆、酒店、景点、博物馆、公园等），来源既可以是 AMap，也可以是 OpenStreetMap 的 Overpass。当地图提供商是 高德 且配置了密钥时使用 AMap；否则使用 Overpass，它免费且无需密钥。

### 照片

从 AMap 搜索添加的地点，会用该 POI 自己的图片作为缩略图。服务器会下载图片并存进照片代理缓存，而不是热链 AMap 的 CDN —— 那些图片 URL 会过期，还会校验 referer，过去这会导致缩略图过一阵子就变空白。图片是在后台抓取的，因此地点会立即出现，缩略图随后通过 WebSocket 送达。已经有图片的地点永远不会被覆盖。

### 路线规划

**驾车、步行和骑行**路线可以来自 AMap，而不是内置的 OSRM 路由器。AMap 的驾车时长考虑了实时路况，这使它在中国城市里比单纯基于距离的估算明显更真实。

路线在服务端抓取 —— 浏览器既看不到 API 密钥，也不需要为 AMap 的路线主机添加网络例外。路线几何会逐顶点从 GCJ-02 转换为 WGS-84，使绘制的线条与地图上的道路吻合。如果 AMap 不可用，应用会像处理任何路线服务故障一样回退到 OSRM。

### 导航

带有 AMap POI id 的地点，会在其导航菜单中得到一项 **AMap**，与 Google Maps、Apple Maps、Waze 等并列。该链接优先使用 POI id，这样打开的是精确的商家而不是一个坐标点；没有 POI id 时，则回退到坐标加地点名称。

## 从 AMap 链接或分享文本导入

地点搜索框接受几种 AMap 输入：

- 桌面端地点链接：`www.amap.com/place/…` 或 `ditu.amap.com/place/…`
- 分享短链接：`surl.amap.com/…` 或 `uri.amap.com/…`
- 裸 POI id（例如 `B000A83M61`）
- AMap 应用里整段 **分享** 文本，原样粘贴

最后一种是最常见的情况，也是这个输入框能容忍一整段文字的原因：应用的复制按钮会把地点名称、地址和链接放进同一个文本块，而链接常常紧贴着前面的中文文字，中间没有空格。Tourism-Team 会从整句话里把 URL 提取出来，而不是要求你自己裁剪。

链接通过 AMap 自己的 POI 查询来解析，因此名称、地址和坐标都会回填，POI id 也会记在该地点上。

> **位置口令无法解析。** 位置口令是一串短数字，没有公开的解析方式 —— AMap 只在
> 自己的应用内打开它。Tourism-Team 能识别出它，并明确说明这一点，而不是拿这串数字去搜索、
> 返回一个自信但错误的地点。

## 需要预期的限制

- **照片和详情只能与 AMap 的收录质量看齐。** 没有照片的 POI 就保持空白缩略图；不会编造占位图。
- **`rating_count` 为空。** AMap 的 v5 API 不报告投票数，而 `business.cost` 是人均价格，因此有意不把它显示为评论数。
- **AMap 以中国为重点。** 在中国大陆以外，它的覆盖很薄 —— 在那些地方请使用 Google Places 或 OpenStreetMap。
- **密钥是实例级的。** 与 Google Places 不同，没有按用户区分的 AMap 密钥。
