# 管理 — 扩展

**扩展** 标签页让你在整个 Tourism-Team 实例范围内启用或禁用可选功能。切换扩展会立即影响所有用户 —— 禁用一个扩展会隐藏它的界面元素，并在实例范围内封锁它的 API 路由。

![扩展概览](assets/Addons-Overview.png)

## 扩展控制什么

每个扩展开关控制一组功能。当你禁用一个扩展时，用户会在应用的所有位置失去对该功能的访问。数据不会被删除；重新启用扩展即恢复对既有数据的访问。

## 扩展分类

扩展分为三个类别，以带标签的分区显示。

### 旅行扩展

旅行扩展添加按行程生效的功能面板。它们会出现在启用了该扩展的每一次旅行中。

默认的旅行扩展是：**列表**、**费用**、**文档**、**协作** 和 **Naver List Import**（默认全部启用）。具体列表取决于你的 Tourism-Team 数据库中注册了什么。

**旅行扩展上的子开关：**

- **列表** —— 启用后会出现一个嵌套的 **行李追踪** 开关。行李追踪让用户把已打包的物品分配到指定的行李中。
- **协作** —— 启用后会出现四个子开关，分别对应各项协作功能：
  - **聊天** —— 旅行内的实时聊天
  - **笔记** —— 共享的旅行笔记
  - **投票** —— 旅行投票
  - **接下来** —— 「接下来」小组件

每个子开关都可以在父扩展保持启用的情况下单独禁用。

### 全局扩展

全局扩展添加不绑定到单次旅行的功能。默认的全局扩展是 **假期**、**足迹**、**收藏** 和 **旅程**。

- **假期** —— 带日历视图的个人假期日程规划器。默认启用。
- **足迹** —— 含旅行统计的已访问国家世界地图。默认启用。
- **收藏** —— 个人地点库：把各次旅行的地点保存进具名列表，复制到任意旅行，并分享它们。**默认禁用。** 见 [收藏](Collections)。
- **旅程** —— 旅行追踪与旅行日志（打卡、照片、每日故事）。**默认禁用。**

**全局扩展上的子项：**

- **旅程** 扩展下方会显示照片来源开关。每个照片来源（例如 Immich、Synology Photos）都可以独立启用或禁用。

### 集成扩展

集成扩展把 Tourism-Team 连接到外部服务。它们大多在启用后还需要额外配置（API 密钥、URL），但不是在管理后台的 **设置** 标签页里 —— 每一个都有自己的位置。

- **MCP** 扩展需要在环境中设置 `APP_URL`。启用后，管理后台会出现 **MCP 访问** 标签页。**默认禁用。** 完整细节见 [MCP 概览](MCP-Overview)。
- **AirTrail** 扩展从自托管的 AirTrail 实例同步航班。**默认禁用。** 这里的开关只是实例级总开关；每位用户各自在 **设置 → 集成** 中连接自己的实例（URL + API 密钥）。
- **AI 解析** 扩展是用于读取 KItinerary 无法识别的订单导入的大模型兜底方案。**默认禁用。** 启用后，它的提供商、基础 URL、API 密钥和模型字段会内联显示在扩展行下方。填写它们会设置对所有用户生效的实例级配置；留空则允许每位用户在 **设置 → 集成** 中配置自己的提供商。见 [AI 订单导入](AI-Booking-Import)。

## 启用或禁用扩展

点击任意扩展行上的开关。改动立即生效 —— 不需要保存按钮。一条简短的 toast 会确认更新。

如果切换失败（例如网络错误），它会回滚到之前的状态。

## 额外配置

有些扩展在可用之前需要凭据或环境变量：

- **旅程** —— 无需任何外部集成就可工作。若要从 Immich 或 Synology Photos 嵌入照片，请启用旅程下列出的对应照片来源开关，然后在 **设置 → 集成** 中按用户配置凭据。见 [照片来源](Photo-Providers)。
- **MCP** —— 需要设置 `APP_URL`，以便 OAuth 重定向 URI 能正确解析。
