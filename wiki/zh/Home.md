# Tourism-Team 文档

Tourism-Team 是一个自托管的实时协作旅行规划工具，基于 AGPL-3.0 许可发布。

![仪表盘](assets/DashboardWidgets.png)

## 功能

### 行程规划
- **拖拽式规划器** —— 把地点安排到日程计划中，支持排序和跨天移动
- **交互式地图** —— 基于 Leaflet 的地图，带照片标记、聚合、路线可视化和可自定义的瓦片源
- **地点搜索** —— 面向中国的高德地图（AMap）、Google Places（照片、评分、营业时间）或 OpenStreetMap（免费，无需 API 密钥）；详见[地点与搜索](Places-and-Search)
- **日程备注** —— 每天可添加带时间戳和图标标记的备注
- **路线优化** —— 自动优化地点顺序，并可导出到 Google Maps 或高德地图
- **天气预报** —— 通过 Open-Meteo 提供 16 天预报（无需 API 密钥），无法获取时回退到历史气候平均值

### 旅行管理
- **预订与订单** —— 记录航班、住宿、餐厅，带确认号和文件附件
- **费用** —— 按分类记录支出，带饼图、按人/按天分摊和多种货币支持（见 [货币](Currencies)）
- **行李清单** —— 按分类的检查清单，支持分配成员、模板和进度跟踪
- **文档管理器** —— 把文档、票据和 PDF 附到旅行、地点或预订上（单个文件最大 50 MB）
- **PDF 导出** —— 把完整行程导出为 PDF，含封面、图片和备注

### 协作
- **实时同步** —— 基于 WebSocket 的实时同步；所有在线成员的改动立即显示
- **多用户** —— 通过角色权限邀请成员
- **邀请链接** —— 注册链接可设置使用次数上限（1–5 次或不限）和有效期
- **OIDC 单点登录** —— 支持 Google、Apple、Authentik、Keycloak 或任何 OIDC 提供方登录
- **两步验证** —— 基于 TOTP 的两步验证，扫码即可配置
- **通行密钥**（管理员启用）—— 免密码的 WebAuthn 登录，支持 Touch ID、Windows Hello、Android 屏幕锁或硬件密钥；持有通行密钥也可满足强制两步验证的策略（见 [通行密钥](Passkeys)）
- **公开分享链接** —— 分享任意旅行的只读视图

### 扩展（管理员可开关）
- **列表** —— 行李清单与待办事项，带模板、成员分配和可选的行李追踪
- **费用** —— 支出记账，带分类明细、分摊和多种货币
- **文档** —— 面向旅行、地点和预订的文件管理器
- **协作** —— 群聊、共享笔记、投票、逐日出席
- **假期** —— 个人假期规划器，带日历视图、法定节假日和结转跟踪
- **足迹** —— 交互式世界地图、心愿单、旅行统计和大洲分布
- **收藏** —— 个人地点库：把各次旅行的地点保存进具名列表，复制到任意旅行，并按成员角色分享（见 [收藏](Collections)）
- **旅程** —— 杂志风格的旅行日志，含日志条目、照片（通过 Immich/Synology Photos）、地图和心情
- **Naver 列表导入** —— 从分享的 Naver 地图列表导入地点
- **MCP** —— 通过 Model Context Protocol（OAuth 2.1）把 Tourism-Team 开放给 AI 助手
- **AirTrail** —— 从自托管的 AirTrail 实例同步航班到旅行中
- **AI 解析** —— 当 KDE Itinerary 读不了确认文件时，用大模型兜底提取订单信息（见 [AI 订单导入](AI-Booking-Import)）

> 仪表盘小组件（汇率换算和时区时钟）是每位用户自己的偏好设置，不是管理员可开关的扩展 —— 见 [仪表盘小组件](Dashboard-Widgets)。
>
> 完整的扩展对照表，含类型和逐项说明，见 [扩展概览](Addons-Overview)。

### 插件
- **沙箱化插件运行时** —— 第三方插件在派生的子进程中运行，RPC 受权限门控，安装时会校验清单和签名，并限制外网访问（见 [插件](Plugins)）
- **插件 SDK** —— 用 `trek-plugin-sdk` npm 包开发和发布插件：开发服务器、预检、签名、提交（见 [插件开发](Plugin-Development)）

### AI / MCP 集成
- **MCP 服务器** —— 内置 Model Context Protocol 服务器，采用 OAuth 2.1 认证
- **150+ 个工具** —— 创建旅行、规划行程、管理预算、发送消息等
- **30 个资源** —— 只读的 `trek://` URI，覆盖旅行、日程、地点、预算、行李、旅程等
- **29 个 OAuth 权限范围** —— 跨 14 个权限组的细粒度授权
- **预置提示词** —— `trip-summary`、`packing-list` 和 `budget-overview` 上下文加载器

### 管理
- 用户管理、邀请链接、打包模板、全局分类
- 扩展管理、API 密钥存储、定时自动备份
- 用于引导和公告的系统公告

> **管理员：** 大部分配置都在管理后台。首次启动时 Tourism-Team 会自动创建一个管理员账户 —— 如果设置了 `ADMIN_EMAIL` / `ADMIN_PASSWORD` 就用这两个值，否则会把随机生成的密码打印到容器日志里。
